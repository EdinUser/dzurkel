Dzurkel 0.7.1 adds clearer Settings and optional-library recovery, fixes preview
opening behavior, and introduces the Dzurkel application icon.

### Changes since 0.7.0

- Settings now has **Integration**, **Previews** and **Libraries** tabs, with
  preview formats grouped by type and supported formats listed in information popups.
- Libraries reports component availability, explains missing readers and offers
  copyable installation commands for reviewed distributions. Dzurkel does not run
  package installers or enable repositories. Highlighting has a persistent checkbox.
- Audio, syntax highlighting and enhanced desktop activation load through optional
  adapters. The core requires Qt base, Qt PDF/PDF Widgets and libzip; optional
  backend SDKs no longer become mandatory application runtime dependencies.
- Known formats with a missing optional reader show file information and an
  **Open Settings** action. Plain text remains available without highlighting.
- Markdown opens at the beginning of the document, and the **Contents** control
  stays in the toolbar when available.
- Images reopen fitted after dismissal, instead of retaining a previous image
  session's maximized/fullscreen state. Maximization within a browsing session
  and saved document geometry retain their existing behavior.
- Custom color icons identify application windows, desktop launchers and the
  Dolphin/Thunar context actions. Small sizes use a simplified design; embedded
  icons also work before installation. The README displays the primary icon.
- Builds generate offline compatibility reports that distinguish dependency
  candidates from validated OS support. Arch VM tooling checks packages with
  optional runtime libraries absent, and CI adds a Debian 12 / Qt 6.4 baseline gate.

### Downloads and upgrading

Choose the runtime installer for your distribution. Downloads are attached after
the release package, test, clean-install and native GNOME checks succeed.

| System | Installer |
| --- | --- |
| Fedora 44, x86_64 | `dzurkel-0.7.1-1.fc44.x86_64.rpm` |
| Debian 13, amd64 | `dzurkel_0.7.1-1_amd64.deb` |
| Current Arch Linux, x86_64 | `dzurkel-0.7.1-1-x86_64.pkg.tar.zst` |

```bash
# Fedora
sudo dnf install ./dzurkel-0.7.1-1.fc44.x86_64.rpm

# Debian 13
sudo apt install ./dzurkel_0.7.1-1_amd64.deb

# Arch Linux: update first, then install
sudo pacman -Syu
sudo pacman -U ./dzurkel-0.7.1-1-x86_64.pkg.tar.zst
```

Download `SHA256SUMS` alongside the installer and verify with
`sha256sum --check --ignore-missing SHA256SUMS`. Packages are unsigned; checksums
verify integrity and are not signatures. No Dzurkel update repository is provided.

Preferences and integration backups are preserved. Existing Thunar actions retain
their old icon until **Restore previous shortcuts…** and **Enable Space shortcut…**
are used after the upgrade. Dolphin Space setup still requires 26.04 or newer.
Quit and remove a user-local development installation's managed executable and
launchers before installing a system package so they do not shadow it.

### Validation and known limits

The release preparation build passed all 23 local CTest suites, including staged
installation and icon payload checks. Earlier checks for the changes since 0.7.0
include a Debian 12 / Qt 6.4.2 baseline build with 20 passing suites, missing-library
checks in a fresh Arch runtime container, and focused native KDE and GNOME Wayland
checks. These results do not certify every distribution or desktop combination.

An intermittent native GNOME table-geometry transition failure was observed; its
focused rerun and the image maximize/dismiss/reopen checks passed. Ubuntu currently
receives general missing-library guidance; Ubuntu-specific copyable installation
commands have not been reviewed. Compatibility reports do not automatically claim
support for older releases, derivatives or unreviewed architectures. Audio formats
and playback still depend on installed backends and codecs.
