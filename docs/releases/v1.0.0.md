# Dzurkel 1.0.0 — Progressive file previews

**Status:** prepared for release in the source checkout. Publishing, tagged CI,
installer upload and stable promotion are separate steps; they are not completed
by this version bump. See the [release process](../releasing.md) and
[available releases](https://github.com/EdinUser/dzurkel/releases).

## Changes since 0.9.0

Dzurkel keeps its quick-preview workflow: select a file, press Space, inspect it
and dismiss it. Content readers now use direct sources without whole-file
temporary copies or whole-source-size admission rejection. Content, metadata,
image, parser and work budgets still apply.

- Plain text, logs and source code load small portions as you scroll. CSV/TSV
  and XLSX load row batches; XLSX keeps worksheet selection and saved values.
- DOCX, DOC, RTF, EPUB, FB2, SFB, MOBI 6 and Markdown load further source content
  through the shared rich-document view. Reader state preserves supported
  formatting, encoding, DOCX list counters, links and bounded images.
- Views keep three adjacent portions and bounded caches, evict older content
  and reload it when revisited. Continuation preserves retained selection,
  reading position and window geometry. Later errors keep useful content visible
  with an explanation; replacement/dismissal cancels obsolete work.
- **End / Ctrl+End** opens the actual last portion of text/log/code files,
  including large SQL exports. **Beginning / Ctrl+Home** returns to the start.
  These jumps seek directly, preserve language/zoom/window and reset selection.
- PDF pages render on demand from the direct source; images decode bounded
  pixels in isolated helpers. Audio/video keep backend-driven streaming.
- Qt image-format selection probes a bounded header, preventing image plugins
  from reading large rejected non-image files during provider selection.
- Window placement and reading/table/image size restoration retain the existing
  desktop-specific solution, including cold opens, transitions and reopening.
- Video windows fit the detected display aspect ratio plus playback controls
  within the screen. The fit happens once; later metadata and seeking preserve
  manual resizing, and maximized/fullscreen windows retain their state.
- Resource preparation, folder navigation and streaming-media helpers cancel
  active requests before detaching still-running process wrappers at application
  exit. This avoids synchronous wrapper-destruction waits even when termination
  remains pending, while preserving normal asynchronous reaping and helper limits.

Existing Dolphin, Nautilus, Thunar and optional KDE chooser integrations remain
available. Optional folder contents sizing, media, highlighting and legacy DOC
extraction keep their existing dependencies and recovery behavior.

## Preview scope and accepted limits

Dzurkel provides a useful peek and ordinary scrolling, rather than an unlimited
document reader or editor. Selection/copy cover resident content; no full-file
index, editing, document search interface or reading-progress database is added.

Evicted structured content may require replay through compressed XML or an
extractor. Very distant replay, eager metadata or a large indivisible paragraph,
table, list or code fence can exceed a budget. Markdown reference discovery may
scan ahead within a bounded work allowance. EPUB retains a bounded chapter tree.
These cases show an explanation; fast logical EOF is promised only by the text
view. The antiword pipe bounds output buffering, not antiword's own allocations.
Application budgets are not an OS memory sandbox.

The selected source-code language stays attached until the preview closes.
Highlighting can lose multiline comment/string context whose opening text was
evicted; perfect lexer-state reconstruction is outside this preview scope.

One native Ubuntu GNOME EPUB regression repeatedly found a one-pixel anchor
difference after continuation (33 px instead of 32 px). It is recorded as a
minor scroll-position discrepancy. That assertion passed on Fedora KDE and Arch
XFCE; its cause on Ubuntu has not been established.

Real network shares, other desktop/backend combinations and comparative
first-paint/total-memory benchmarks need broader evidence. Existing transport
access does not establish universal remote performance. Direct SFTP remains
experimental and disabled by default. See [preview limits](../previews.md),
[location compatibility](../compatibility.md) and [validation](../testing.md).

## Validation

The progressive-loading implementation was validated before this version bump
under the 0.9.0 development version:

- Fedora: all 34 suites; five affected ASan/UBSan suites with leak detection;
  focused native KDE Wayland document/text checks and 70 CSV/XLSX results.
- Ubuntu GNOME Wayland: all 31 configured suites, native text EOF checks and
  70 CSV/XLSX results. Selected document checks passed apart from the one-pixel
  EPUB discrepancy above. Actual Files Space/Escape, SQL EOF and progressive
  DOCX/Markdown scrolling were exercised on the installed development build.
- Arch XFCE/X11: all 34 package-build suites, separate missing-library runtime
  checks, package installation/integrity, 17 focused native text/document results
  and 70 CSV/XLSX results. Actual Thunar Space/Escape and SQL/DOCX/Markdown
  browsing passed against the installed package.

Each CSV/XLSX run skipped one optional private sample. These records identify
their exact binaries and environments; they are not tagged 1.0.0 release CI or
new sanitizer results after the version change. The latest local version-bump
checks are recorded in [testing](../testing.md).

After the version bump, the full local 1.0.0 build and all 34 CTest suites passed
(123.48 s), including staged installation and optional-adapter recovery. Package
source fields, desktop adapter ID, executable version and generated compatibility
report agree on 1.0.0. Local documentation links/anchors and whitespace checks
also passed. This is local source validation, not installer publication or a new
VM/sanitizer run.

The final shutdown and video-sizing changes passed all 35 local CTest targets
(131.55 s). The new shutdown suite includes 28 isolated subprocess cases with
simulated undelivered termination; it does not reproduce actual uninterruptible
kernel I/O. Generated video tests cover landscape/portrait fitting, manual
resizing and maximized/fullscreen preservation. The user installed the updated
application in Ubuntu and Arch Linux VMs and confirmed video sizing works as
expected on both.

The user also reported immediate text-end navigation and subsequent lazy loading
on a 3.8 GB SQL dump, and responsive random-position playback of an approximately
78 GB MKV over an SMB share. These are individual real-file acceptance
observations, not controlled latency or cold-cache benchmarks. Tagged package
builds, clean-install checks and native GNOME acceptance remain release gates.

## Installation and upgrading

Planned runtime filenames are `dzurkel-1.0.0-1.fc44.x86_64.rpm`,
`dzurkel_1.0.0-1_amd64.deb` and `dzurkel-1.0.0-1-x86_64.pkg.tar.zst`.
Only use files actually attached to the release after validation, and verify
`SHA256SUMS`. See [installation and removal](../installation.md).

Quit the resident process before replacing its executable. Update matching
adapters together; the desktop adapter ID is release-specific. Settings and
shortcut backups remain per-user, and installing/upgrading does not enable or
rewrite file-manager shortcuts. No new parser, transport or layout dependency
is required for progressive loading.
