Dzurkel 0.8.0 adds streaming video previews and shared audio/video playback
controls, with bounded source read-ahead for slow shares.

### Changes since 0.7.1

- Preview MP4/M4V, MKV, WebM, MOV, AVI, MPG/MPEG, OGV and WMV in an
  aspect-preserving video view. Playback depends on installed Qt media backends
  and codecs; a filename or container does not guarantee decoding support.
- Audio and video autoplay with sound and share the running session's mute and
  volume choices. Play/pause uses **P**; **Space/Escape** continue to dismiss.
  Timeline controls support seeking when the source/backend permits it.
- Actual media tracks choose the music or video view without reopening the
  source, preserving audio-only MP4 support and music cover-art presentation.
- Local files and mounted shares use the existing isolated file-reading helper.
  A fixed 512 KiB read-ahead window reduces repeated filesystem reads, while
  IPC transfers stay at most 64 KiB. Dzurkel creates no whole-file media snapshot.
- Loading waits for a valid video frame. Slow reads and seeks receive explicit
  feedback, and closing/changing previews cancels source access independently
  of its read deadline. Old playback errors cannot replace a newer preview.
- Incompatible media adapters now report their interface mismatch and the
  need to reinstall a matching application/adapter set, rather than “Unknown error.”
- Plain text wraps to the preview width by default. **Wrap lines** in the
  toolbar remembers the user's choice without modifying whitespace or files.
- Settings adds **OS compatibility…**, showing the build's requirements and
  distinguishing reviewed dependency candidates from validated OS support.
- Debian packages recommend the audio/video runtime libraries alongside
  highlighting. Development SDKs are needed only when building; the adapters
  remain optional at runtime and baseline previews still work without them.

### Downloads and upgrading

The package workflow attaches installers only after release validation succeeds.

| System | Installer |
| --- | --- |
| Fedora 44, x86_64 | `dzurkel-0.8.0-1.fc44.x86_64.rpm` |
| Debian 13, amd64 | `dzurkel_0.8.0-1_amd64.deb` |
| Current Arch Linux, x86_64 | `dzurkel-0.8.0-1-x86_64.pkg.tar.zst` |

```bash
# Fedora
sudo dnf install ./dzurkel-0.8.0-1.fc44.x86_64.rpm

# Debian 13
sudo apt install ./dzurkel_0.8.0-1_amd64.deb

# Arch Linux: update first, then install
sudo pacman -Syu
sudo pacman -U ./dzurkel-0.8.0-1-x86_64.pkg.tar.zst
```

Download `SHA256SUMS` alongside the installer and verify with
`sha256sum --check --ignore-missing SHA256SUMS`. Packages are unsigned; checksums
verify integrity and are not signatures. No Dzurkel update repository is provided.

Quit the resident Dzurkel process before upgrading and restart it afterward so
the executable and optional adapters match. Preferences and integration backups
are preserved. A user-local development executable can shadow a system package;
follow the installation guide when switching between them. Dolphin Space setup
still requires Dolphin 26.04 or newer. Ubuntu is a development-test platform,
not a release DEB target; choose a package built for your distribution/release.

### Validation and known limits

Development validation includes the full local CTest suite, focused media
ASan/UBSan checks, generated silent video and audio-only MP4 fixtures, front/tail
MP4 indexes, MKV/WebM playback, delayed reads, seek-to-end, repeated teardown and
missing/incompatible adapter checks. Read-only local and mounted-CIFS samples
passed integrated native KDE Wayland checks; an actual compositor capture was
visually inspected. See the testing record for the versioned release checks.

Per-read latency injection improved seek behavior with bounded read-ahead, but
does not establish cold-cache bandwidth performance or real network-disconnection
recovery. Codec/backend coverage, actual missing-audio-device playback, full
GNOME/XFCE video acceptance and hard decoder/GPU memory bounds remain separate
checks. Automatic reconnect/resume, playlists and advanced subtitle/track
controls are outside this release. Public HTTP/live-stream URLs are not added.

Release package builds, clean install/removal and the native GNOME gate still
run when the GitHub release/prerelease is published. Pushes alone do not trigger
that pipeline; local test results do not substitute for it.
